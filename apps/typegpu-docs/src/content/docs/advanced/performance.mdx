## Leaving out features your app doesn't use

Methods of the root object, like `root.createTexture()`, can't be removed by bundlers even when an app never calls them,
so every app ships the code behind them. If your app doesn't use a feature, you can tell the bundler with its `define` option,
and the code behind that feature will be left out of the bundle.

| Flag | Leaves out | Then throws |
| --- | --- | --- |
| `__TYPEGPU_NO_TEXTURES__` | Textures, texture views and samplers created through the root | `root.createTexture()`, `root.createSampler()`, `root.createComparisonSampler()` |
| `__TYPEGPU_NO_QUERY_SETS__` | Query sets, also used by `.withPerformanceCallback()` | `root.createQuerySet()` |
| `__TYPEGPU_NO_CONSOLE_LOG__` | Support for `console.log` inside shaders (calls compile to nothing) | - |

```ts
// vite.config.ts
import { defineConfig } from 'vite';
import typegpu from 'unplugin-typegpu/vite';

export default defineConfig({
  plugins: [typegpu()],
  define: {
    __TYPEGPU_NO_TEXTURES__: 'true',
    __TYPEGPU_NO_QUERY_SETS__: 'true',
    __TYPEGPU_NO_CONSOLE_LOG__: 'true',
  },
});
```

In an app that renders particles with one compute and one render pipeline, the three flags together shrink the bundle by 33 kB minified (9.5 kB gzipped).
Apps that don't define the flags behave exactly as before.

## Compiling the bundle eagerly

Shader code generation runs during the first frame, on code the JavaScript engine has never seen, so the engine spends part of that time compiling functions on their first call.
Chromium-based browsers (since version 136) accept a hint that compiles every function in a file up front. In Vite, add it to the start of each output file:

```ts
// vite.config.ts
export default defineConfig({
  build: {
    rolldownOptions: {
      output: {
        // Added after minification, which would otherwise strip the comment
        postBanner: '//# allFunctionsCalledOnLoad',
      },
    },
  },
});
```

On a throttled mobile profile, this got the first frame of our examples on screen 60 to 90 ms sooner.

## Submitting draws and dispatches together

Calling `.draw()` or `.dispatchWorkgroups()` on a pipeline without an explicit command encoder submits its work right away.
Each submission takes a bit of CPU time, which adds up in apps that run many passes per frame, like fluid simulations.
With `unstable_batchSubmits`, those submissions wait until the current task's synchronous code is done, and are then submitted together:

```ts
const root = await tgpu.init({ unstable_batchSubmits: true });
```

TypeGPU's own operations, like `buffer.write()`, `buffer.read()` or `texture.destroy()`, first submit the work made before them, so the GPU still sees everything in order.
Using `root.device` directly does not, so in an app that does, prefer TypeGPU's methods, or record the passes into one encoder from `root['~unstable'].createCommandEncoder()`.

In a fluid simulation that runs about 25 compute passes per frame, this cut the median CPU time per frame by about a fifth, and that of the slowest frames by 40%, on a throttled mobile profile.
